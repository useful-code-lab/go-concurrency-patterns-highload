# Go Concurrency Patterns for High-Load Systems

Практический набор реализаций конкурентных паттернов на **Go** для построения систем, которые умеют параллельно обрабатывать задачи, контролировать нагрузку, масштабировать воркеры и корректно завершать работу.

Проект подойдет разработчикам, которые хотят не просто прочитать о `goroutine`, `channel`, `context` и `sync.WaitGroup`, а увидеть, **как эти механизмы применяются при проектировании реальных систем обработки нагрузки**.

## Что можно получить из проекта

Изучая этот репозиторий, вы сможете:

* понять, как организовать взаимодействие между большим количеством горутин;
* увидеть практическое применение каналов Go для передачи задач и результатов;
* реализовать Worker Pool для параллельной обработки задач;
* ограничивать интенсивность выполнения операций с помощью Rate Limiter;
* распределять задачи между несколькими исполнителями;
* объединять несколько потоков данных в единый канал;
* автоматически масштабировать количество воркеров в зависимости от нагрузки;
* реализовывать Backpressure и не допускать бесконтрольного роста очереди;
* корректно останавливать горутины и освобождать ресурсы;
* использовать `context` для отмены операций и ограничения времени выполнения;
* находить и предотвращать состояния гонки с помощью `go test -race`.

Проект особенно полезен как **практический справочник по конкурентному программированию на Go**: отдельные реализации можно использовать как основу для собственных сервисов, очередей задач, обработчиков событий и высоконагруженных компонентов.

## Реализованные паттерны

### 1. Диспетчеризация задач по специализированным воркерам

**Bank Queue / Dispatcher Pattern**

Пример системы электронной очереди банка, в которой диспетчер распределяет клиентов между специалистами в зависимости от типа услуги.

Показывает:

* распределение задач между специализированными воркерами;
* использование персональных каналов;
* координацию свободных исполнителей;
* `sync.WaitGroup` для контроля жизненного цикла;
* корректное завершение всех воркеров.

Реализация:

`cmd/bank_queue/bank_queue.go`

---

### 2. Rate Limiter

**Token Bucket / управление скоростью выполнения**

Ограничивает количество операций за определенный период времени и позволяет контролировать поток входящих задач.

Полезен для:

* защиты внешних API;
* ограничения нагрузки на сервис;
* контроля частоты запросов;
* построения throttling-механизмов.

В реализации используются `time.Ticker`, каналы, `context` и асинхронное выполнение задач.

Реализация:

`cmd/tb_rate_limiter/tb_rate_limiter.go`

---

### 3. Fan-In

**Мультиплексирование нескольких каналов в один**

Несколько источников данных объединяются в единый выходной канал.

Паттерн полезен для:

* объединения результатов нескольких источников;
* построения pipeline;
* обработки параллельных потоков данных;
* организации конкурентного producer/consumer взаимодействия.

Реализация учитывает отмену через `context`, закрытие исходных каналов, `nil`-каналы и корректное закрытие результирующего канала.

Реализация:

`cmd/multiplex_fan_in/multiplex_fan_in.go`

---

### 4. Fan-Out

**Распределение задач между несколькими воркерами**

Один поток задач распределяется между несколькими горутинами.

Паттерн позволяет:

* выполнять независимые задачи параллельно;
* создавать Worker Pool;
* контролировать количество одновременно работающих воркеров;
* собирать результаты выполнения через Fan-In.

Реализация:

`cmd/fan_out/fan_out.go`

---

### 5. Adaptive Worker Pool

**Динамическое масштабирование пула воркеров**

Worker Pool автоматически увеличивает количество исполнителей при росте нагрузки и уменьшает его при простое.

В проекте рассматриваются:

* `minWorkers` и `maxWorkers`;
* динамическое масштабирование;
* Idle Timeout;
* Backpressure;
* ограничение размера очереди;
* Graceful Shutdown;
* контроль состояния воркеров;
* защита от Race Conditions;
* проверка через `go test -race`.

Такой подход можно использовать как основу для систем, где нагрузка изменяется во времени и фиксированного количества воркеров недостаточно.

Реализация:

`cmd/adaptive_worker_pool/adaptive_worker_pool.go`

---

### 6. Task Dispatcher

**Отказоустойчивый планировщик задач с ограничением параллелизма**

Унифицированная система выполнения различных типов задач через общий интерфейс `Task`.

Демонстрирует:

* единый интерфейс для разных видов задач;
* фиксированный лимит одновременно работающих воркеров;
* `context` для отмены и таймаутов;
* обработку результатов и ошибок;
* безопасное завершение Worker Pool;
* использование `goroutines`, `channels`, `WaitGroup` и интерфейсов.

Реализация:

`cmd/task_sync/task_sync.go`

## Как использовать репозиторий

Каждый паттерн представлен отдельной реализацией в директории `cmd`.

Можно открыть интересующий пример, изучить код и запустить его самостоятельно:

```bash
go run ./cmd/bank_queue
go run ./cmd/tb_rate_limiter
go run ./cmd/multiplex_fan_in
go run ./cmd/fan_out
go run ./cmd/adaptive_worker_pool
go run ./cmd/task_sync
```

Для проверки конкурентной безопасности:

```bash
go test -race ./...
```

## Что изучать в первую очередь

Если вы только начинаете разбираться с конкурентностью в Go, удобно двигаться следующим путем:

**Fan-Out → Fan-In → Worker Pool → Rate Limiter → Adaptive Worker Pool → Task Dispatcher**

Так постепенно можно перейти от базового распределения задач к более сложной системе управления нагрузкой и жизненным циклом конкурентных компонентов.
